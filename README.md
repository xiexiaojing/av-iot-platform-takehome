# 天枢 / 天机 / 灵机 / 天工 —— 12 个月架构演进方案（架构师笔试题）

**仓库名**：`av-iot-platform-takehome`　|　**主语言**：Java　|　**结构**：架构文档 + 可运行实现 + AI 代码审阅

[![CI](https://github.com/xiexiaojing/av-iot-platform-takehome/actions/workflows/ci.yml/badge.svg)](https://github.com/xiexiaojing/av-iot-platform-takehome/actions/workflows/ci.yml)　CI 每次 push 自动执行：编译 + 单测 + 冒烟 + 并发幂等（Temurin JDK 17 / 21）

**主语言：Java**（编码部分用 Java 17+ 语法编写，JDK 自带 `javac` 即可编译，不依赖 Maven/Gradle/外网；
辅助语言：Shell（`scripts/smoke.sh`）、Python（`scripts/load_demo.py`））

## 三句话结论

1. **不做中台、不做多活、不自研协议栈**：8–15 人团队的瓶颈不在技术先进度，而在"定制分叉"与"交付可重复性"，
   因此 12 个月只做三件硬事——**设备接入标准化（南向协议收敛 + 指令语义统一）、产品内核与项目扩展分层（配置/插件/旁路三级）、
   私有化交付工程化（离线包 + 版本迁移 + 一键回滚）**。
2. **一切围绕"指令语义正确"这一个中心**：设备接入与音视频媒体面**必须解耦**，指令下发走"受理 ≠ 成功"的显式状态机
   （PENDING/SUCCESS/FAILED + 超时兜底 + 幂等键），杜绝"云端显示成功、设备并未执行"这类吃掉政企信任的事故。
3. **P0（90 天）不碰重构，先建"看得见的底线"**：把分叉收口成配置与插件、把私有化升级变成可回滚流水线、把演示环境的
   指令语义跑通并可自动化验证；P1 才做协议网关与媒体面统一；P2 才考虑国密/双活/自研协议栈这类投入产出比低的大工程。

## 自评

- **最能代表水平的部分**：`02-关键链路详设.md`（2.A 写到接口/主题/状态机/容量级假设）与
  `coding/src/c2d/CommandService.java`（幂等、显式失败、超时兜底、并发安全四条硬约束全部可运行、可单测）。
- **自认较弱**：`02` 的 2.B 音视频媒体面深度主要来自通用工程经验，弱于设备接入侧；
  私有化国产化（麒麟/统信 + 国密）部分只写到"可测可交付"的方法层面，未落到具体版本矩阵。
- **总耗时**：约 1 个工作日（文档 0.5 天 + 编码 0.5 天 + 复核）。
- **可运行性声明**：`coding/` 的编译、单测、冒烟、并发幂等四步在本机实际跑通并贴出了输出（第 0 节），
  CI 会在每次 push 自动复跑（`main` 分支可查看 Actions 结果）。
